## 2026-08-06: NER + tokenizer-adaptation diagnosis (NEW - supersedes older NER numbers)

Two root causes of the "low NER" result were found and verified empirically:

1. **Prefix-space harness bug.** `tok(words, is_split_into_words=True)` with ByteLevel
   BPE (ModernBERT family) encodes 100% of words WITHOUT the leading-space `G` prefix,
   i.e. out-of-distribution vs pretraining ("militants" -> `m/ilit/ants` instead of
   `Gmilitants`). WordPiece (ConfliBERT-2021) is immune, so the old comparison was
   biased against every ModernBERT-family model. Fixed via `--prefix-space` in
   `src/eval/finetune_benchmark.py` (and passthrough in `scripts/corrected_bench.py`);
   the `add_prefix_space=True` kwarg is silently IGNORED by the fast tokenizer, the
   backend `pre_tokenizer` must be replaced.
2. **Truncated LR grid.** ModernBERT NER F1 rises monotonically through 8e-5 (old grid
   max); 1.6e-4 is far better. ConfliBERT-2021 peaks at 5e-5, so the old grid
   handicapped only the modern models.

## Key gotchas (also in project memory)
- Peak VRAM must stay < ~20GB or WSL2 spills to host RAM (2.5x slowdown + "device not ready"). bsz 8 is safe.
- Do NOT use PYTORCH_CUDA_ALLOC_CONF=expandable_segments (crashes on this WSL2/driver).
- Packed token memmaps must be on ext4 (`/root/packed`), not `/mnt/f` (9p random reads are slow).
- NEVER launch training with `pkill -f train_dapt.py` in the command (self-matches the launcher).
- Inline shell vars / for-loops inside `wsl bash -lc` get eaten; use literal args, python heredocs, or .sh files.
